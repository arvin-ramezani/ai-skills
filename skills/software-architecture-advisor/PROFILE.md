## Coding preferences

- Use descriptive names; avoid abbreviations.
- Prefer clean structure over explanatory comments.
- Do not comment on what code does.
- A rare comment may explain why a non-obvious decision exists.
- When demonstrating SOLID, add a short comment identifying the principle and architectural reason.
- Avoid premature interfaces, factories, repositories, or layers without a real variation or boundary.

## Environments

- Local development runs on Windows 10 using PowerShell.
- Servers run Ubuntu using a Bash-compatible shell.
- Label commands by environment and use the correct syntax.
